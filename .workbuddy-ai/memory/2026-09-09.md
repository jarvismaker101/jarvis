# 2026-09-09

## Implemented Fable-5 audit group G3 (Request Identity & Streaming Contract: F23, F26, F25, F30)

Reference docs: `~/Downloads/whole audit by fable.pdf` (extracted to `data/_audit_pdf_text.txt`
via pypdf because the PDF is too large to read directly) and `~/Downloads/plan.txt`.

### What was already implemented before this session
- `backend/services/request_registry.py` — the F23 execute-once registry (get_or_create /
  try_start / numbered seq buffers / events_after / interrupt / heartbeat) and the F26 event
  protocol constants (delta/replace/progress/completed/interrupted/error). Only needed a
  `replace()` helper and a fix so `stream()` flushes buffered events *before* waiting on the
  heartbeat condition (reattaching clients were being delayed a full heartbeat).

### What I added (the actual remaining gaps)
- **F25 – pure, cancellable speculation** (`backend/core/brain.py`)
  - `_build_chat_messages(..., speculative=..., history=...)`: speculative builds return
    `path="needs_search"` instead of calling `search_internet` (no external effects); the
    lookup now happens in the selected route inside `handle_chat`.
  - Removed the blind `history[:-1]` slice when a speculative build runs before the new user
    turn is committed.
  - `_ChatRacer`: bounded queue (`_RACER_QUEUE_LIMIT = 256`), immutable history snapshot,
    `cancel()` now sets a real `threading.Event` that is checked by the generator loop and
    forwarded to the provider clients (`cancel=` kwarg) so in-flight HTTP stops immediately.
  - Provider clients (`fireworks_client`, `openai_compat_client`, `gemini_client`) accept
    `cancel=` and close responses in `finally`.
- **F26 – decision before speech** (`handle_chat`): uncertainty→clarification is now decided
  before the answer is streamed/emitted; if the answer was already spoken it is kept verbatim
  instead of silently swapping in a permission question.
- **F23 – client side** (`frontend/renderer.js`): migrated off the old `payload.delta` /
  `payload.done` protocol. Added `newRequestId()`, `lastEventId` tracking, `handleFrame()`
  (6 event types, `completed` is terminal authority applied verbatim), `attach()` with
  `last_event_id` resume, and `recover()` — which **replaces** `fallbackToAsk` (deleted) with
  a `GET /ask/status/{request_id}` lookup + reattach so a drop never re-executes a request.
  `MAX_RECONNECTS = 3`.
- **F30 – publish early, enrich later** (`brain.py` + `backend/api/routes.py` + `main.js`)
  - `push_screen_answer()` now returns the answer id and carries `id` / `request_id` /
    `capture_id`; progress ("analysing screen") is emitted while vision runs.
  - New `_enrich_screen_answer()` bounded decoration phase (daemon thread, 8s) patches the
    **same answer id** with topic images / exploration links.
  - `/screen-answer` PATCH rejects stale writes with HTTP 409 (`stale screen answer` /
    `stale screen capture`), so a late answer can never overwrite a newer question.
  - `main.js` overlay re-renders when the same answer id gains a new revision.

### Bugs found and fixed along the way
- `backend/api/routes.py::ask` assigned the `(state, created)` tuple from
  `req_registry.get_or_create()` without unpacking → **every `POST /ask` raised
  `AttributeError: 'tuple' object has no attribute 'started'`**. Fixed to
  `state, _created = ...`. (Caught by the new G3 test, not by the existing suite.)

### Second-pass review fixes (after the first "done" report)
- **`_enrich_screen_answer` deadline bug (F30)**: when the 8s enrichment deadline was hit
  after `build_explore_links` had run, the function `return`ed and **threw away the links it
  had just built**, despite the log message saying "links only". Now it sets
  `show_images = False` and falls through so the links are published and only the slow image
  phase is skipped. Covered by
  `test_enrichment_deadline_ships_links_without_images`.
- Verified against the verbatim audit text (`data/_audit_pdf_text.txt` lines 243-330) that all
  four F-numbers are satisfied, including the two easiest to miss:
  - F26's "feed accepted final-channel deltas into one StreamSpeaker for typed requests" —
    already wired in `routes._run_request_worker` (`speak_stream=True` from `/ask/stream`,
    StreamSpeaker fed from `on_delta`, `speaker.finish()` then `_maybe_speak` fallback when
    nothing was spoken).
  - F23's "reconnect resumes without re-executing" on the *server* too — `/task/stop` calls
    `req_registry.interrupt_active()` so attached clients get a terminal `interrupted` frame
    instead of hanging.
- `replace` is defined in the protocol and handled by the client but is not currently emitted
  by any server path; `completed` already supersedes accumulated deltas, so it is unused
  rather than missing. Left as protocol surface for G4.

## Implemented Fable-5 audit group G4 (Coding Interface: F11, F15)

Plan source: `~/Downloads/plan.txt` line 13-14. Audit text: F11 = PDF p4 ("Give Native Coding
an Inspection/Edit Loop"), F15 = PDF p5 ("Upgrade the Editor Bridge Into a Coding Interface")
— re-extracted this session to `~/Downloads/audit_fable.txt` (pypdf, 19 pages; strip NUL bytes
or ripgrep treats it as binary).

### Key finding: G4 was ~85% landed but F15 was a broken shell
`code_tools.py` (F11) and `editor_bridge.py` (F15) were complete, and `agent.py` had all the
dispatch branches for the new tools — **but 8 renderer helpers were referenced and never
defined**, so EVERY `editor.*` step raised `NameError` at runtime:
`_editor_state_text`, `_editor_tool_text`, `_editor_buffer_text`, `_editor_diagnostics_text`,
`_editor_symbols_text`, `_editor_references_text`, `_editor_search_text`, `_editor_tests_text`.
Verify with `grep -n "^def " agent.py` — the call sites existed, the defs did not.

### What I added
- **F15 renderers** (`backend/services/task_agent/agent.py`, new block before `_execute_step`).
  Shapes taken from the real extension source `integrations/jarvis-editor-bridge/extension.js`
  (it IS in the repo, despite plan.txt saying "not supplied"). Ranges from the bridge are
  **0-based** (converted to 1-based for display); `readBuffer.startLine/endLine` and
  `workspaceSearch` match lines are **1-based**. Added `_SEVERITY_LABELS` (vscode
  DiagnosticSeverity 0-3) and `_SYMBOL_KINDS` (vscode SymbolKind 0-25) numeric->word maps.
- **Honest failures for editor tools**: `_editor_tool_text(tool, result, render)` now prefixes
  `<tool> failed: <reason>` so `execute_plan`'s existing `failed_prefix` check records a
  failure (previously a bridge error string was returned as a successful step). It keeps the
  structured body on failure too — a failing test run still ships its output.
- **F11/F15 gaps in the G1 closed loop**: `code.apply_patch` added to the deterministic
  postcondition set (it is a write); `pattern` added to `_step_target` (code.search's target is
  a pattern, not a path); `editor.*` branches added to `_ok_fragment` (F11 had code.* branches
  only); `editor.apply_workspace_edit` added to `CONFIRM_SENSITIVE_PREVIEW` with a preview that
  names the files being edited.
- Hoisted `_STEP_TEXT_LIMIT` above `_execute_step` (was defined after it; the renderers need it
  at def time).
