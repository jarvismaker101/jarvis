### What I added
- **NEW `backend/services/research_browser.py` (F27)** — one daemon thread + one asyncio loop +
  one persistent Chrome context for the whole process. `submit(fn, task_id)` for sync job
  bodies (run ON the owner thread), `run(coro_fn, task_id)` for async ones (run on the owner
  loop). `maybe_await()` lets one body drive a real async page and a MagicMock page. Module
  singleton keyed on `(profile, channel)`; idle TTL via `JARVIS_RESEARCH_IDLE_TTL`.
- **`research_service.py` (F28)** — `async def _research_job` replaces the serial loop:
  `asyncio.Semaphore(3)` on fetches, `Semaphore(2)` on Gemini notes, `asyncio.gather` (returns
  in submission order → Brave's ranking survives), `dedupe_results` / `_canonical_url`
  (strips www/scheme-case/trailing-slash/fragment/utm+fbclid params), monotonic deadline
  checked before every fetch and note, `_emit`/`_publish` for immediate progress + incremental
  evidence.
- **`research_service.py` (F48)** — `build_evidence_item` / `build_overview_item` /
  `annotate_corroboration`; provenance, source_url, supporting_span, retrieved_at, uncertainty.
  The AI overview is `secondary` and is explicitly NOT counted as corroboration. Overview title
  changed from the invented "Google AI Overview" to "Brave Search AI Overview (secondary
  source)".
- **NEW `backend/services/provenance.py`** — one shared vocabulary (`observed`/`quoted`/
  `inferred`/`secondary`/`externally_checked`) + `normalise_provenance` (rejects invented
  labels). `research_service` re-exports the constants so existing imports/tests keep working.
- **`screen_analyzer.py` (F48 screen half)** — `_ANALYSIS_PROMPT` no longer tells the model to
  "Use Google Search ... verify any claims" (search grounding is OFF), and now asks for a
  `provenance` per evidence item. Evidence is sanitised with provenance/uncertainty/
  observed_at; a model-supplied `externally_checked` is downgraded to `observed`. Added
  `needs_external_check()` (narrow regex gate) + `_external_check()` which actually runs
  `quick_search.fetch_ai_overview_text` so a verification question performs a real lookup.
- **`quick_search.py` (F27)** — no longer launches/closes Chrome; submits to the warm worker.
  Split into `_quick_search_job` (extraction only, on the browser thread) and spoken
  summarisation afterwards off it. Replaced Ask-tab `networkidle` + disclaimer-length polling
  with `_answer_container_text` + `_wait_for_answer_update` (bounded: stable text or timeout).
- **`brain.py` (F28)** — `handle_research_intent` now supplies `on_progress` and `on_evidence`
  (it supplied neither before). New `push_research_progress()` posts to a new
  `POST/GET /research-progress` endpoint in `routes.py` — a research run outlives the chat
  request, so it cannot ride the SSE stream.

### Bugs found and fixed along the way
- **Pages leaked for unnamed tasks**: `research_browser.submit()` / `run()` tracked pages only
  under a `task_id`, so a job submitted with `task_id=None` never closed its page — a leak for
  the lifetime of the warm context. `ResearchTask` now keeps its own page list and always
  closes it; `submit` closes the page directly when unnamed. (Caught by the new tests.)
- **Deadline misreported as a user cancel**: the pre-flight stop check in `_research_job`
  returned `stopped=True` for a deadline expiry, contradicting the run's own contract. Added
  `_cancelled_now()` so only an explicit cancel is "stopped" — a deadline keeps what was
  gathered.

### Patterns worth reusing next time
- Seam pattern for browser tests: patch `research_service._browser_run` /
  `quick_search._browser_submit` and inject a MagicMock task/page — never launch Chrome.
- To test the worker itself, patch `playwright.async_api.async_playwright` with a fake whose
  `start()` returns a fake playwright/chromium/context; the real thread+loop then runs.
- Cancellation: reuse `backend/services/jobs.py` `JobToken` (per-job, monotonic deadline,
  `register_stop_handler`). Legacy module-level `_STOP_REQUESTED` stays as a bridge, exactly
  like `browser_agent.py` F20.
